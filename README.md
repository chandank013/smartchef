# SmartChef: AI-Powered Recipe & Meal Planning Assistant

Enter the ingredients you have, pick a dietary preference and serving size, and SmartChef suggests recipes generated by an LLM, each with a matching food photo. No login and no database: favorites and history live in your browser.

## Features

- Ingredient input (max 200 characters), dietary filter (Any, Vegetarian, Vegan, Gluten-Free, Keto) and servings (1 to 8)
- Recipe cards with photo, cooking time, calories, dietary label and key ingredients
- Recipe details view with full ingredient quantities and numbered steps
- Save and remove favorites, plus the five most recent searches (stored in `localStorage`)
- Light and dark theme, responsive layout for desktop, tablet and mobile
- Designed empty, loading, error and image-fallback states, with a Retry action
- Secure backend proxy: LLM and image API keys never reach the browser
- In-memory response cache and per-IP rate limiting to control API cost

## Tech stack

| Layer | Technology |
|---|---|
| Frontend | React 18, Vite, plain CSS (hooks and Context, no state library) |
| Backend | Node.js 18+, Express |
| LLM | Groq, OpenAI, Gemini or Anthropic (your choice), or `mock` for keyless demos |
| Images | Unsplash or Pexels (free tier) |
| Caching / limits | `node-cache`, `express-rate-limit` |
| Persistence | Browser `localStorage` only (no database) |

## Getting started

**Prerequisites:** Node.js 18 or newer and npm.

### 1. Start the backend
```bash
cd server
npm install
cp .env.example .env       # Windows: copy .env.example .env
npm run dev                # http://localhost:5000
```
With the default `LLM_PROVIDER=mock` the API returns sample recipes, so you can run the whole app without any API keys.

### 2. Start the frontend (second terminal)
```bash
cd client
npm install
npm run dev                # http://localhost:5173
```
The Vite dev server forwards `/api` requests to `http://localhost:5000`, so no CORS setup is needed locally.

### 3. Use real AI recipes and photos
Edit `server/.env`:
```env
LLM_PROVIDER=groq            # groq | openai | gemini | anthropic
LLM_API_KEY=your-key-here
IMAGE_PROVIDER=unsplash      # unsplash | pexels
IMAGE_API_KEY=your-image-key
```
Restart the server after changing `.env`.

## Environment variables

### Server (`server/.env`)

| Variable | Default | Description |
|---|---|---|
| `PORT` | `5000` | Port the API listens on |
| `CLIENT_ORIGIN` | `http://localhost:5173` | Allowed frontend origin(s) for CORS, comma-separated |
| `LLM_PROVIDER` | `mock` | `groq`, `openai`, `gemini`, `anthropic` or `mock` |
| `LLM_API_KEY` | none | Key for the chosen provider (server-side only) |
| `LLM_MODEL` | provider default | Optional override (defaults: `openai/gpt-oss-120b`, `gpt-4o-mini`, `gemini-2.0-flash`, `claude-sonnet-4-6`) |
| `LLM_TIMEOUT_MS` | `30000` | Timeout for LLM calls |
| `IMAGE_PROVIDER` | `none` | `unsplash`, `pexels` or `none` |
| `IMAGE_API_KEY` | none | Image API key (server-side only) |
| `CACHE_TTL_SECONDS` | `600` | How long identical requests are cached |
| `RATE_LIMIT_PER_MIN` | `10` | Requests allowed per IP per minute |

### Client (`client/.env`)

| Variable | Description |
|---|---|
| `VITE_API_URL` | Leave empty in development. In production, set to the deployed backend URL. |
| `VITE_PROXY_TARGET` | Dev proxy target if the backend is not on port 5000 |

Never put the LLM or image keys in the client; only the server reads them.

## API

### `POST /api/generate-recipe`

Request:
```json
{ "ingredients": ["rice", "tomato", "onion"], "diet": "vegetarian", "servings": 2 }
```

Success (200):
```json
{
  "success": true,
  "cached": false,
  "recipes": [{
    "title": "Tomato Onion Rice",
    "description": "A simple and flavorful rice dish.",
    "time": "25 mins",
    "calories": 320,
    "imageUrl": "https://images.unsplash.com/...",
    "ingredients": [{ "name": "Rice", "quantity": "1 cup" }],
    "steps": ["Cook rice separately and set aside."]
  }]
}
```
`imageUrl` is `null` when no image provider is configured or the lookup fails; the client then shows its fallback.

Errors return `{ "success": false, "error": "message" }`:

| Status | Cause |
|---|---|
| 400 | Invalid input (empty list, too long, unknown diet, servings outside 1 to 8) |
| 429 | Rate limit exceeded |
| 502 | LLM error or malformed LLM output |
| 504 | LLM timed out |
| 500 | Server misconfiguration or unexpected error |

`GET /api/health` returns `{ "ok": true }`.

## How it works

1. The React form validates input and calls `POST /api/generate-recipe` through the `useRecipeApi` hook.
2. The server rate-limits, validates and sanitizes the input, then checks the in-memory cache (key = sorted ingredients + diet + servings).
3. On a cache miss, `llmService` sends a structured prompt that asks for JSON only, then parses and validates the reply.
4. `imageService` fetches a photo per recipe title. A failed lookup never fails the request.
5. The result is cached for 10 minutes and returned. The client renders cards and keeps results, favorites and history in `localStorage`.

## Deployment

- **Backend (Render, Railway or similar):** set the root to `server`, start command `npm start`, and add the environment variables above in the host's dashboard (never commit `.env`). Set `CLIENT_ORIGIN` to your frontend URL.
- **Frontend (Netlify or Vercel):** set the root to `client`, build command `npm run build`, publish directory `dist`, and set `VITE_API_URL` to the backend URL.

## Troubleshooting

- **"Cannot reach the server":** the backend is not running, or `VITE_API_URL` / the dev proxy points to the wrong address.
- **CORS error in production:** add the exact frontend URL to `CLIENT_ORIGIN`.
- **Recipes appear but with placeholder images:** `IMAGE_PROVIDER` or `IMAGE_API_KEY` is missing or invalid; check the server log.
- **"AI service returned an error":** check `LLM_API_KEY`, the provider name and `LLM_MODEL`; the details are in the server console.
- **429 responses while testing:** raise `RATE_LIMIT_PER_MIN` during development.

## Limitations

- No database: favorites and history are per browser and per device.
- The cache and rate-limit counters are in memory, so they reset on restart and are not shared across multiple server instances.
- Nutritional values are AI estimates, not verified data.
- Unsplash's terms ask for photographer attribution, which this version does not display.
- There is no automated test suite yet.

## Future improvements

- Database (for example MongoDB) and user accounts for cross-device favorites
- Redis for a shared cache and rate limiting
- Shopping list from missing ingredients, and a recipe API for verified nutrition data
- Automated tests (Vitest and React Testing Library on the client, Supertest on the server)
